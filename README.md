# ABYSS — 심해 낚시 일지

작은 배에서 시작해 낚싯줄을 늘리고 다섯 해역의 깊은 층을 조사하는 PC 브라우저 게임입니다. 원본 저장소의 Phaser 바다·보트·물고기, 보스 아트, 효과음과 입력 처리를 사용합니다.

## PC에서 시작하기

1. 프로젝트 ZIP의 압축을 풀고 `package.json`이 있는 폴더에서 터미널을 엽니다.
2. Node.js 22.12 이상과 pnpm을 설치한 뒤 아래 명령을 차례로 실행합니다.
3. 터미널에 표시된 주소를 브라우저에서 엽니다. 기본 주소는 http://127.0.0.1:5173 입니다. Windows에서는 같은 폴더의 `start-game.cmd`도 사용할 수 있습니다.

```sh
pnpm install
pnpm dev
```

## 첫 해역에서 누를 버튼

- **낚싯줄 던지기** 또는 **Space**로 시작합니다. 화면에 보이는 물고기를 직접 클릭해도 됩니다. 두 방식 모두 선택한 층에서 헤엄치는 같은 어종 풀을 사용합니다. 산호해에서는 마우스를 움직이거나 좌우 방향키를 눌러 물고기를 구역 안에 유지하세요.
- **장비 공방 → 낚싯줄**을 누르세요. 시작 자금은 100 G, 첫 판매금은 최소 20 G, 첫 줄은 120 G입니다. 버튼을 누르는 순간 최대 수심이 100 m에서 200 m로 늘어납니다. **깊은 층**을 눌러 바다와 어종을 바꿉니다.
- **다음 목표**를 누르면 현재 필요한 장비 버튼으로 이동하거나 필요한 행동을 시작합니다. 깊은 층 1마리를 포함해 수동으로 6마리를 잡고 **산호의 수호자 도전**을 누르세요. 보스의 첫 움직임은 평소 해역에서 배운 조작입니다. 이후 빛나는 원에서 마우스 또는 Space/Enter로 누르거나 길게 누릅니다.
- 보스를 이기고 **다음 해역**을 누르면 푸른 해류의 얕은 층에 도착합니다. 출항은 무료입니다. 이전 해역은 항해 지도에서 다시 선택할 수 있습니다.
- 낚시를 놓치면 **즉시 재도전**이 뜹니다. 같은 해역에서 수동 낚시를 세 번 놓치면 다음 시도의 판정이 넓어집니다. 보스를 세 번 놓치면 **연습 도움 켜고 도전**을 선택할 수 있습니다. 이 승리도 출항에 반영됩니다.
- 선택 장비인 릴은 위험 장력에서 버티는 시간을 단계마다 0.2초 늘립니다(최대 0.8초). 홀드 위치를 잠깐 벗어나도 버틸 수 있는 시간은 단계마다 0.1초 늘어납니다. 낚싯대·어선·미페 결합은 기존처럼 따로 쓸 수 있습니다.

| 해역 | 얕은 층 / 깊은 층(m) | 조사 | 줄 / 릴(G) | 첫 보스(G) | 일반 판매 하한(G) |
|---|---|---:|---:|---:|---:|
| 햇살 산호해 | 0–100 / 100–200 | 6 | 120 / 100 | 40 | 20 |
| 푸른 해류 | 200–600 / 600–1,000 | 14 | 260 / 200 | 100 | 30 |
| 황혼의 심해 | 1,000–2,000 / 2,000–3,000 | 20 | 520 / 400 | 160 | 42 |
| 검은 열수구 | 3,000–4,500 / 4,500–6,000 | 30 | 950 / 750 | 250 | 55 |
| 마리아나 해구 | 6,000–8,500 / 8,500–11,000 | 36 | 1,500 / 1,200 | 500 | 75 |

영수증은 어종·크기·판매가와 추가 보상을 표시합니다. PC의 애니메이션 줄이기 설정을 사용하면 포획 후 끌어올리기·반짝임을 건너뜁니다. 도감과 판매금은 연출 전에 저장됩니다. 큰 개체와 황금 발견은 도감에 남습니다. 황금 확률은 2.5%, 동일 크기 판매가의 4배입니다. 어시장 구매만 한 종에는 시장 입수가 표시됩니다. 연구 보상은 해당 해역에서 서로 다른 5종을 직접 잡았을 때 한 번 받습니다. 새 어획 카드의 용도는 수집·강화입니다. 시장에서 산 카드와 이관한 거래 가능 여분만 매도할 수 있고 기본 카드 한 장을 보호합니다.

그물·시장·원정은 본편 조사 수에 영향을 주지 않습니다. 원정은 마지막 보스 승리 후 열립니다. 경로 선택, 유물, 선체 수리와 원정 기록을 유지합니다. 기존 원정 완주자는 바로 다시 출항할 수 있습니다.

## 저장 이어하기와 백업

- 같은 브라우저에서 **같은 주소**를 여세요. 주소의 프로토콜, 호스트, 포트가 모두 같아야 합니다. 예를 들어 localhost와 127.0.0.1은 저장 공간이 다릅니다.
- v2가 없으면 `abyss-fishing-v1`을 읽어서 별도 키 `abyss-fishing-v2`에 저장하고 다시 읽어 확인합니다. v1 원문은 그대로 남습니다. v2가 있으면 그것을 우선합니다.
- 보유 골드·포획·황금·장비·카드·의뢰·연구·보스·선장·원정 기록과 기존 해역 접근을 이관합니다. 이전 보스를 깬 곳에는 깊은 층용 줄이 있습니다. 구형 누적 포획은 역사 기록에 남고, 새 조사와 크기 기록은 확인 가능한 새 포획부터 쌓입니다. 옛 포획을 다시 정산하지 않습니다.
- 다른 PC, 브라우저 또는 비공개 사이트로 옮길 때는 **플레이 안내 → 기록 내보내기**로 JSON을 보관한 뒤, 새 주소에서 **기록 가져오기**를 누르세요. v1·v2 파일을 검증하고 교체 여부를 묻습니다. 취소하거나 검증에 실패하면 현재 저장을 유지합니다. 내보내기는 v2 형식입니다.
- 화면 상단에 저장 오류가 나오면 플레이 안내에서 현재 기록을 내보낼 수 있습니다. 저장 공간이 가득 찬 경우 파일을 보관한 뒤 여유 공간을 확보하세요.

## Firebase 선장 랭킹

게임만 할 때는 위의 두 실행 명령으로 충분합니다. 로컬 랭킹을 쓸 때는 Java 21이 있는 PC에서 **두 번째 터미널**을 열고 아래 명령을 실행합니다. 첫 실행은 도구와 Firestore 에뮬레이터를 다운로드합니다.

```sh
pnpm ranking
```

**선장 랭킹**을 열고 이름을 입력한 뒤 **내 기록 등록**을 누릅니다. 보스 승리 해역 수, 누적 수동 조사 수 순으로 상위 50명을 표시합니다. 브라우저마다 익명 선장 ID를 하나 사용합니다. 같은 ID로 재등록하면 최고 기록을 유지합니다. 랭킹을 쓰지 않아도 저장과 낚시는 동작합니다. 로컬 순위표는 같은 PC의 에뮬레이터에 연결된 브라우저끼리 공유됩니다. Ctrl+C로 정상 종료하면 `.ranking-data`에 보관합니다.

**인터넷 공동 랭킹**을 운영하려면 Firebase 프로젝트에 웹 앱을 등록하고 Authentication의 익명 로그인과 Cloud Firestore를 켭니다. 프로젝트 루트의 `.env.local`에 웹 앱 설정을 JSON으로 넣고 개발 서버를 다시 시작하거나 다시 빌드하세요. 값은 Firebase 콘솔의 웹 앱 설정에 있습니다.

```dotenv
VITE_FIREBASE_CONFIG='{"apiKey":"웹 API 키","projectId":"프로젝트 ID","appId":"웹 앱 ID","authDomain":"프로젝트.firebaseapp.com"}'
```

운영 프로젝트에 포함된 `firestore.rules`를 적용합니다. Firebase CLI에 해당 계정으로 로그인한 상태에서 `firebase deploy --only firestore:rules --project 프로젝트ID`를 실행할 수 있습니다. 읽기는 인증된 사용자, 쓰기는 본인 기록으로 제한되며 점수 형식과 최고 기록을 검증합니다. 이 순위표는 로컬 저장의 기록을 등록하는 친선 랭킹입니다. 플레이 과정을 서버에서 인증해야 하는 경쟁전은 별도 설계가 필요합니다.

## 개발 및 검증

```sh
pnpm test
pnpm build
pnpm preview
```

PC 브라우저 회귀 테스트는 `pnpm dev` 실행 중 별도 터미널에서 진행합니다. `CHROME_PATH`에 설치된 Chrome 또는 Chromium 실행 파일의 절대 경로를 지정하고 `pnpm test:browser`를 실행하세요. Firebase 에뮬레이터까지 켜고 `RANKING_QA=1`을 지정하면 두 브라우저 간 등록·조회도 검사합니다. 테스트는 별도 임시 브라우저 프로필을 사용합니다.

기준 커밋은 `4cf40028453157e0a79fa238a4040cade60872dd`입니다. 확인한 원격 HEAD와 일치했습니다. 개편 전 빌드는 성공했고 115개 테스트 중 111개가 통과했습니다. 실패한 4개는 저장 왕복의 선장 XP, 전체 항해의 저장 왕복, 라운드 증가, 심해 드롭 분포에 관한 항목이었습니다. 새 검증에서는 기존 50개 ID, 재고·강화, 최초 보상, XP 보존을 유지하며 해금·라운드·수심 추첨·가져오기 오류 동작을 새 규칙으로 검사합니다.

`src/catalog.ts`에 해역과 안정적인 어종 ID, 수심·어종 풀·조작·보스·가격·크기·특징을 모았습니다. `src/model.ts`는 결제·판매·기록·해금·저장, `src/main.ts`는 UI와 입력, `src/scene.ts`는 바다·보트·물고기, `src/art.ts`와 `src/effects.ts`는 그림과 연출을 담당합니다.

### 진행 속도 측정

PC Chromium에서 새 저장으로, 얕은 층과 깊은 층 각각의 첫 일반·고급 어종을 고정해 스크립트가 화면에 표시된 조작을 수행했습니다. 황금, 그물, 시장, 일일 의뢰, 원정, 선택 장비 구매를 사용하지 않았습니다. 게임 시계와 라운드 대기를 가속하지 않았습니다. 선수처럼 정확한 입력을 반복하는 경로입니다.

| 사건 | 실행 시작 후 실측 |
|---|---:|
| 첫 포획 자동 판매 | 8초 |
| 첫 줄 구매 및 깊은 층 진입 | 9초 |
| 산호해 첫 보스 승리 | 1분 14초 |
| 푸른 해류 보스 승리 | 3분 56초 |
| 검은 열수구 도착 | 7분 36초 |
| 마리아나 깊은 층 진입 | 11분 42초 |
| 마지막 보스 승리 | 16분 49초 |

5분 시점은 황혼의 심해 조사 6/20, 15분 시점은 마리아나 조사 26/36이었습니다. 기획상 5·15·30·60분 시점은 각각 산호해·푸른 해류·황혼의 심해·검은 열수구 전후가 목표입니다. 일반 어종을 찾아 정확히 입력하는 경로는 이 목표보다 빠릅니다. 초보자의 실패와 선택 시간이 포함된 사람 대상 측정은 별도로 필요합니다.

27분 시점에는 다섯 보스 승리 후 마리아나 수동 조사 115마리를 기록했습니다. 최종 요청에 맞춰 60분 측정은 조기에 종료했습니다. 단위·진행·저장 테스트는 총 116개가 통과했습니다. PC Chromium의 Canvas와 WebGL에서 포획·줄 구매·깊은 층 새로고침을 확인했고, 1366×768 화면에서 목표·캐스팅 버튼·줄 구매 버튼이 첫 화면 안에 들어오는 것도 확인했습니다.
